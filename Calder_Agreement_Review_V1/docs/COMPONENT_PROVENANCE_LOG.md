# Component provenance log

Required by Section 12.1 of the project brief. One row per significant module, tagged
**predominantly AI-generated** (written here as **Worked with AI**), **predominantly hand-written**,
or **substantially modified from generated code**. This replaces the general syllabus's prompt-and-response appendix, which doesn't
work for agentic coding tools.

The whole application was built with AI coding assistance throughout, with the team
directing scope, reviewing output, and making the product/legal judgment calls (category
selection, scope cuts, what ships). A fourth label, **third-party / vendored**, is used below for
code or text the team did not write and did not ask an AI assistant to write — library internals
and the unmodified Bonterms/Common Paper source documents — since the brief's three categories all
presuppose the team or its AI assistant authored the content.

Updated as of 2026-10-24. Update this table as modules change; don't let it go stale.

On 2026-10-24 the interface (`src/Workspace.tsx`), the data layer (`src/lib/data.ts`) and the stylesheets were split into the modules below without changing any code; each split was checked line for line. Those rows carry over the provenance of the single row they replaced (Worked with AI). A teammate who wrote or substantially rewrote one of them should correct its row.

**Authors (PR)** lists each GitHub user whose pull requests wrote at least 5% of the module's current lines, largest share first, with those PR numbers. "Initial upload" means the first files added directly to the repository rather than through a pull request. Lines were traced with `git blame`, following code moved between files, so the 2026-10-24 split (PR #32, which only moved code) is not counted as authorship.
